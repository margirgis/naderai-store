# مستند المتطلبات

## 1. نظرة عامة على التطبيق

### 1.1 اسم التطبيق
Nader AI - تطبيق Android

### 1.2 وصف التطبيق
تطبيق Android يعرض لوحة تحكم Nader AI (https://g1.appmedo.com) داخل WebView، مع قدرة على قراءة رسائل SMS من Vodafone Cash تلقائياً لتأكيد طلبات شحن المحفظة، والتكامل مع Supabase Edge Functions للمزامنة مع النظام الخلفي.

### 1.3 السياق التقني
- المشروع الحالي: React + Vite + shadcn/ui في /workspace/app-dpgpkghtekg1
- الموقع المنشور: https://g1.appmedo.com
- Backend: Supabase Edge Functions
- هذا تطبيق جديد (لا يستخدم naderai-app القديم في tasks/)

## 2. المستخدمون وسيناريوهات الاستخدام

### 2.1 المستخدمون المستهدفون
- العملاء: يستخدمون التطبيق للوصول إلى لوحة التحكم وشراء/تفعيل الخدمات الرقمية (Google Gemini Pro، اشتراكات)
- النظام: يقرأ رسائل SMS تلقائياً لتأكيد المعاملات

### 2.2 سيناريوهات الاستخدام الأساسية
- المستخدم يفتح التطبيق ويمنح صلاحيات SMS
- المستخدم يتصفح الموقع https://g1.appmedo.com داخل التطبيق
- المستخدم يطلب شحن محفظته عبر الموقع
- التطبيق يقرأ رسائل Vodafone Cash تلقائياً ويرسلها للنظام الخلفي
- النظام يؤكد المعاملة تلقائياً

## 3. هيكل الصفحات والوظائف

```
تطبيق Nader AI Android
├── شاشة الصلاحيات
├── شاشة الدعوة (اختيارية)
├── الشاشة الرئيسية (WebView)
└── خدمة Foreground Service
    ├── قراءة SMS
    └── إرسال Heartbeat
```

### 3.1 شاشة الصلاحيات

#### 3.1.1 طلب صلاحية READ_SMS
- عرض رسالة توضيحية: التطبيق يحتاج صلاحية قراءة الرسائل لتأكيد معاملات Vodafone Cash تلقائياً
- زر منح الصلاحية
- التحقق من منح الصلاحية

#### 3.1.2 طلب صلاحية POST_NOTIFICATIONS
- عرض رسالة توضيحية: التطبيق يحتاج صلاحية الإشعارات لإبقاء الخدمة نشطة
- زر منح الصلاحية

#### 3.1.3 الانتقال للشاشة التالية
- بعد منح الصلاحيات: الانتقال لشاشة الدعوة (إن وُجدت) أو الشاشة الرئيسية

### 3.2 شاشة الدعوة (اختيارية)

#### 3.2.1 عرض محتوى الدعوة
- عرض نص ترحيبي
- عرض مميزات التطبيق

#### 3.2.2 زر البدء
- الانتقال للشاشة الرئيسية

### 3.3 الشاشة الرئيسية (WebView)

#### 3.3.1 عرض الموقع
- تحميل https://g1.appmedo.com في WebView
- دعم JavaScript
- دعم التنقل بين الصفحات

#### 3.3.2 شريط التقدم
- عرض شريط تقدم أثناء تحميل الصفحات

#### 3.3.3 معالجة الأخطاء
- عرض رسالة خطأ عند فشل التحميل
- زر إعادة المحاولة

#### 3.3.4 زر الرجوع
- الرجوع للصفحة السابقة في WebView
- الخروج من التطبيق عند عدم وجود صفحات سابقة

### 3.4 خدمة Foreground Service

#### 3.4.1 بدء الخدمة
- بدء الخدمة تلقائياً عند فتح التطبيق
- عرض إشعار دائم: \"Nader AI يعمل في الخلفية\"

#### 3.4.2 قراءة رسائل SMS
- الاستماع لرسائل SMS الجديدة
- فلترة رسائل Vodafone Cash فقط
- استخراج البيانات:
  - رقم المرسل
  - المبلغ
  - رقم المعاملة
  - نص الرسالة الكامل

#### 3.4.3 إرسال البيانات للنظام الخلفي
- إرسال بيانات الرسالة إلى Supabase Edge Function
- Endpoint: POST /functions/v1/sms-verification
- Body:
  - device_id
  - sender_phone
  - amount
  - transaction_id
  - sms_body
  - timestamp

#### 3.4.4 إرسال Heartbeat
- إرسال heartbeat كل 30 ثانية
- Endpoint: POST /functions/v1/device-heartbeat
- Body:
  - device_id
  - app_version
  - timestamp

#### 3.4.5 إيقاف الخدمة
- إيقاف الخدمة عند إغلاق التطبيق

## 4. القواعد والمنطق

### 4.1 معرّف الجهاز (Device ID)
- توليد Device ID فريد عند أول تشغيل
- حفظ Device ID محلياً في SharedPreferences
- استخدام Device ID في جميع الطلبات للنظام الخلفي

### 4.2 صلاحيات التطبيق
- READ_SMS: لقراءة رسائل SMS
- INTERNET: للاتصال بالنظام الخلفي
- FOREGROUND_SERVICE: لتشغيل الخدمة في الخلفية
- POST_NOTIFICATIONS: لعرض إشعار الخدمة
- RECEIVE_BOOT_COMPLETED: لبدء الخدمة تلقائياً بعد إعادة تشغيل الجهاز

### 4.3 فلترة رسائل Vodafone Cash
- فحص رقم المرسل: يبدأ بـ \"Vodafone Cash\" أو رقم محدد
- فحص نص الرسالة: يحتوي على كلمات مفتاحية (تحويل، مبلغ، رصيد)

### 4.4 التكامل مع Supabase
- استخدام Supabase URL و Anon Key من Environment Variables
- إرسال طلبات HTTP إلى Edge Functions
- معالجة الاستجابات والأخطاء

### 4.5 WebView Configuration
- تفعيل JavaScript
- تفعيل DOM Storage
- تفعيل File Access
- User Agent: تضمين \"NaderAI-Android\" للتعريف

### 4.6 إعادة المحاولة
- عند فشل إرسال البيانات: إعادة المحاولة 3 مرات
- تأخير 5 ثوانٍ بين المحاولات

### 4.7 بدء الخدمة تلقائياً
- بدء Foreground Service تلقائياً بعد إعادة تشغيل الجهاز
- استخدام BroadcastReceiver للاستماع لـ BOOT_COMPLETED

## 5. التسليم والنشر

### 5.1 بناء APK
- إنشاء APK موقّع (Signed APK)
- استخدام Keystore للتوقيع

### 5.2 CI/CD
- إعداد GitHub Actions لبناء APK تلقائياً
- رفع APK على GitHub Releases عند إنشاء Tag جديد
- Workflow يتضمن:
  - Checkout code
  - Setup Java
  - Build APK
  - Sign APK
  - Create Release
  - Upload APK

### 5.3 الإصدارات
- استخدام Semantic Versioning (مثال: v1.0.0)
- تحديث versionCode و versionName في build.gradle

## 6. الحالات الاستثنائية والحدودية

| الحالة | السلوك المتوقع |
|--------|----------------|
| المستخدم يرفض صلاحية READ_SMS | عرض رسالة توضيحية، التطبيق لا يعمل بدون الصلاحية |
| فشل تحميل الموقع في WebView | عرض رسالة خطأ + زر إعادة المحاولة |
| فشل إرسال بيانات SMS للنظام | إعادة المحاولة 3 مرات، ثم حفظ البيانات محلياً للإرسال لاحقاً |
| الجهاز غير متصل بالإنترنت | عرض رسالة \"لا يوجد اتصال بالإنترنت\" في WebView |
| استقبال رسالة SMS غير Vodafone Cash | تجاهل الرسالة |
| الخدمة تتوقف بسبب نظام Android | إعادة تشغيل الخدمة تلقائياً |
| المستخدم يضغط زر الرجوع في الشاشة الرئيسية | الرجوع للصفحة السابقة في WebView، أو الخروج من التطبيق |
| استقبال رسالة SMS أثناء إيقاف الخدمة | قراءة الرسالة عند بدء الخدمة مرة أخرى |

## 7. معايير القبول

1. المستخدم يفتح التطبيق ويرى شاشة الصلاحيات
2. المستخدم يمنح صلاحية READ_SMS و POST_NOTIFICATIONS
3. التطبيق ينتقل للشاشة الرئيسية ويعرض https://g1.appmedo.com في WebView
4. المستخدم يتصفح الموقع ويطلب شحن محفظته
5. المستخدم يحوّل المبلغ عبر Vodafone Cash
6. التطبيق يستقبل رسالة SMS من Vodafone Cash
7. Foreground Service يقرأ الرسالة ويستخرج البيانات
8. التطبيق يرسل البيانات إلى Supabase Edge Function بنجاح
9. النظام الخلفي يؤكد المعاملة ويضيف الكريدت للعميل
10. المستخدم يرى رصيده محدّثاً في الموقع
11. التطبيق يرسل heartbeat كل 30 ثانية بنجاح
12. المستخدم يعيد تشغيل الجهاز، Foreground Service يبدأ تلقائياً
13. GitHub Actions يبني APK ويرفعه على GitHub Releases عند إنشاء Tag جديد
